# sen policy

**Status:** built (printing and `--check`; the Health page warning is not yet built)

Prints the Tetragon TracingPolicy sentient needs, for the agents installed under your home directory. It only prints: nothing is installed or changed, and no privileges are needed. You install it yourself, then restart Tetragon (it does not reload a changed policy). The policy names the agent binaries installed now as exact paths, so after an agent update run it again, install it, and restart Tetragon.

```
$ sen policy
# sentient: kernel events for the coding agent's process tree.
# Generated by `sen policy`; install it with
#   sen policy | sudo tee /etc/tetragon/tetragon.tp.d/sentient.yaml
# and restart Tetragon (it does not reload a changed policy).
# Every hook is limited to the agent binaries below and what they start.
apiVersion: cilium.io/v1alpha1
kind: TracingPolicy
...

$ sen policy | sudo tee /etc/tetragon/tetragon.tp.d/sentient.yaml >/dev/null
$ sudo systemctl restart tetragon

$ sen policy --home /home/alice --home /home/bob
```

`--home` is repeatable and defaults to your home directory.

## `--check`

Compares the installed policy file with the agents installed now, and the running agents with the moment Tetragon started (it loads the policy then). Needs no privileges and no sentientd: it reads the policy file and `/proc`. Exits 0 when everything is fine and 1 otherwise, so it can be scripted. A `!` marks a problem. `--policy-file` says where the policy is installed (default `/etc/tetragon/tetragon.tp.d/sentient.yaml`).

It catches three silent failures: the policy does not list an agent that was updated in, Tetragon was not restarted after the policy changed, and an agent that was already running when the policy loaded (its commands are recorded, but the files and connections they touch are not).

```
$ sen policy --check
  policy:   /etc/tetragon/tetragon.tp.d/sentient.yaml lists the 5 agent binaries installed now
  tetragon: running since 2026-10-24 02:12:03, policy loaded then
  agents:   1 running, all started after the policy loaded
$ echo $?
0

$ sen policy --check
  policy:   /etc/tetragon/tetragon.tp.d/sentient.yaml lists the 5 agent binaries installed now
  tetragon: running since 2026-10-23 02:38:20, policy loaded then
! agents:   claude 2.1.305 (pid 118708) started 2026-10-22 02:47:23, before the policy loaded. Its commands are recorded, but not the files and connections they touch. Restart it for full capture
sen: policy check failed
$ echo $?
1
```

Other problems it reports, each with the fix:

- `policy: not installed (...). Install it: sen policy | sudo tee ...`
- `policy: ... does not list <binary>. An agent update stops the policy matching. Rerun sen policy, install it, restart Tetragon, then restart the agent`
- `tetragon: running since ..., but the policy file changed after that. Restart Tetragon (it does not reload a changed policy)`
- `tetragon: not running. Start it, then restart your agents`
